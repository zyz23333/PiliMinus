# Android 稍后再看专注模式规格

Status: ready-for-agent
Created: 2026-10-11
Platform: Android
Priority: 减少观看时的选择与干扰，尽快得到可用版本
Implemented: 2026-10-11
Implementation: [实施与验证记录](implementation.md)

## Problem Statement

现有客户端提供推荐、动态、搜索、收藏、评论、相关推荐等大量功能。用户希望观看自己已经加入稍后再看的视频，但完整列表和其他浏览入口会带来挑选、跳转和分心的机会。

用户需要一个专门处理稍后再看的 Android 应用：打开后只面对当前一个视频，按固定顺序观看，自己决定什么时候处理完，再进入下一个项目。

首要目标是快速收窄使用流程。用户接受保留冗余代码及依赖，因此第一版不以删光其他模块、缩小安装包或重构整个客户端为目标。

## Solution

基于现有客户端实现一个固定的精简使用流程：

1. 未登录时提供现有登录入口；登录后进入稍后再看首页。
2. 从 B 站账号的完整稍后再看队列中，按最早添加优先选出队首；首页只显示这一个视频。
3. 用户点击当前视频，进入精简后的现有播放页。
4. 播放页保留正常播放控制、基本视频信息、合集和分 P 选集，并支持合集／分 P 内自动续播。
5. 用户返回首页，点击“完成”，将首页这一项从 B 站稍后再看中移除；成功后显示新的队首。

视频在 B 站官方客户端或网页加入稍后再看。本应用提供同步和刷新，不提供搜索、浏览或粘贴链接添加视频的入口。

首页不提供跳过、随机选择、切换排序、观看状态筛选或完整队列浏览。播放结束不自动移除项目，也不自动开始稍后再看队列中的下一个项目。

仅保留登录、退出账号、稍后再看首页、播放页和相关设置入口。关闭外部链接直达内容页面的能力。精简规则固定生效，不能通过旧偏好或设置重新打开被隐藏的功能。

## User Stories

1. 作为希望专注观看的 Android 用户，我希望打开应用就进入稍后再看，以便直接处理自己已经选好的内容。
2. 作为尚未登录的用户，我希望能使用现有登录方式登录，以便读取自己的 B 站稍后再看队列。
3. 作为已登录用户，我希望保留退出账号入口，以便管理当前使用的账号。
4. 作为用户，我希望首页使用 B 站账号中的完整队列，以便与官方客户端和网页保持一致。
5. 作为用户，我希望按最早添加优先观看，以便从积压最久的项目开始处理。
6. 作为用户，我希望首页一次只显示一个视频，以便减少比较和挑选。
7. 作为用户，我希望横屏、竖屏和滚动时都不会出现其他队列项，以便单视频规则始终一致。
8. 作为用户，我希望已被 B 站标记看完的项目仍参与排队，以便自己决定它是否已经处理完。
9. 作为用户，我希望当前项目持续留在首页直到完成，以便不会通过跳过来不断挑选其他视频。
10. 作为用户，我希望点击当前视频就能使用现有播放器，以便沿用熟悉的播放体验。
11. 作为用户，我希望保留标题和 UP 主名称等基本信息，以便知道自己正在观看什么。
12. 作为用户，我希望播放页隐藏评论、相关推荐和其他浏览入口，以便注意力留在当前内容上。
13. 作为用户，我希望保留当前视频的合集选集列表，以便观看同一合集中的其他集。
14. 作为用户，我希望保留多 P 视频的选集列表，以便选择当前视频的不同分 P。
15. 作为用户，我希望可以手动切换合集或分 P，以便继续观看所需的章节。
16. 作为用户，我希望合集和分 P 内可以自动续播，以便减少连续观看同一内容时的操作。
17. 作为用户，我希望当前合集或分 P 播到末尾后停止，以便由自己决定什么时候完成当前队列项。
18. 作为用户，我希望播放结束不自动删除稍后再看项目，以便观看状态不会替代我的完成决定。
19. 作为用户，我希望“完成”按钮只出现在首页，以便保持播放页简洁，并明确要处理的项目。
20. 作为用户，我希望切换合集中的其他集后，首页的完成对象仍是最初打开的队列项，以便完成时不会删错视频。
21. 作为用户，我希望完成操作同步移除 B 站稍后再看中的这一项，以便队列在不同客户端保持一致。
22. 作为用户，我希望完成成功后首页显示新的队首，以便继续按固定顺序处理队列。
23. 作为用户，我希望移除失败时保留当前项目并能重试，以便网络错误不会让我误以为已经完成。
24. 作为用户，我希望在官方客户端或网页添加视频后，可以在本应用刷新队列，以便继续使用现有添加习惯。
25. 作为用户，我希望空队列与加载失败有不同提示，以便判断是已经处理完还是需要重试。
26. 作为用户，我希望失效或无法播放的项目仍能在首页完成移除，以便队列不会永久卡在这一项。
27. 作为用户，我希望保留播放、字幕、弹幕和外观相关设置，以便沿用自己的观看习惯。
28. 作为用户，我希望设置页不提供恢复推荐、评论、其他导航或跨队列连播的开关，以便精简规则保持稳定。
29. 作为用户，我希望应用不接管其他应用中的内容链接，以便观看从首页当前项目开始。
30. 作为已有安装的用户，我希望升级后旧导航、筛选、排序和连播偏好也遵循新规则，以便无需自己重新配置。

## Implementation Decisions

### 已确认的产品边界

- 第一版仅以 Android 为运行与验收目标。保留现有跨平台工程和冗余代码，不开展其他平台适配或代码清理。
- 应用的可访问流程收窄为登录／退出账号、稍后再看首页、播放页和相关设置。推荐、热门、动态、搜索、收藏夹、用户主页、私信等功能不提供入口。
- 复用现有登录、账号管理、B 站请求、播放器、选集组件和设置能力；不引入独立后端或另一套本地稍后再看队列。
- 添加视频在 B 站官方客户端或网页完成。本应用不提供添加视频、搜索视频或粘贴链接添加的功能。

### 首页与队列规则

- B 站主账号的稍后再看列表是队列来源。完整队列保留在服务端，首页只呈现队首；“显示一个视频”不代表将服务端列表裁剪为一项，也不要求一次性下载全部队列数据。
- 使用现有最早添加排序和“全部”筛选。未看、未看完、已看完的项目都可以成为队首。
- 首页只展示一个队列项及其必要信息、播放入口、“完成”、刷新、账号和设置入口。布局变化、滚动、长按或更多菜单不能暴露完整队列或跳过能力。
- 不提供跳过、随机、上一项／下一项、排序切换、多选、批量删除和一键清空等队列操作。
- 初始化和用户主动刷新时同步服务端队列。刷新后按服务端当前顺序选出队首，不按观看进度排除项目。
- 沿用现有分页数据读取能力；移除后以重新同步的队首确认下一个项目，不通过简单递增旧列表索引推进，避免删除导致分页位置变化而漏项。

### “完成”的含义与请求处理

- “完成”是显式的队列移除操作，仅位于首页；它不等同于播放完成事件或观看记录中的“已看完”状态。
- 完成对象绑定首页当前队列项的身份。播放页切换合集集数或分 P，不修改该完成对象。
- 复用现有稍后再看单项移除接口，仅移除当前队列项，并同步到 B 站主账号。
- 发起请求时保留当前项目并展示处理状态；请求期间防止重复提交，也避免对正在处理的队首执行冲突操作。
- 只有服务端确认移除成功后，才推进到新的队首。移除失败时保留当前项目、显示失败提示并允许重试。
- 移除成功后若重新读取队列失败，进入可重试的读取状态；不能将已经移除的旧项目再次作为待完成项目提交。
- 请求与触发时的账号及项目绑定。退出或切换账号后，迟到的旧响应不能覆盖新会话的首页数据。
- 队列为空时显示明确的空状态和刷新入口；加载失败时显示错误及重试入口，两者不能混同。
- 失效或不支持播放的队首保留必要信息、失败提示和“完成”入口，由用户明确移除；不自动跳过或自动清空。

### 播放页、合集与分 P

- 复用现有播放页与播放器，保留正常播放控制和标题、UP 主名称等基本信息。其他社交、浏览及队列管理操作不属于此精简流程。
- 隐藏评论、相关推荐，以及 UP 主主页、搜索、收藏夹等页面的跳转入口；检查头像、标签、简介链接和更多菜单等入口，避免仅隐藏主导航。
- 保留当前视频所属合集和分 P 的选集列表、手动切换与现有展示能力。选集列表可以显示多个集数，这是单视频首页规则的明确例外。
- 可以从当前合集的选集列表切换到该合集中的其他集，即使这些集没有单独加入稍后再看；它们仍属于本次合集观看流程，不改变首页队列项。
- 保留合集／分 P 内部自动续播，播到末尾后停止。不能继续到其他稍后再看项目、相关推荐或循环回合集开头。
- 不展示完整稍后再看播放队列，不提供跨队列的上一项／下一项或“播放全部”；这些能力与合集／分 P 选集区分处理。
- 播放页不提供“完成”按钮。用户返回首页后，完成最初打开的队列项。
- 沿用已有播放进度、画质、倍速、全屏、字幕和弹幕能力；观看进度上报不会触发队列移除，也不影响首页“全部”筛选。

### 设置、入口与已有安装

- 复用现有设置页，保留播放、字幕、弹幕、外观等相关设置；隐藏其他功能设置。
- 精简规则固定生效。不能通过设置恢复推荐、评论、原主导航、完整队列或跨队列／相关推荐连播。
- 检查已有安装的持久偏好，使旧启动页、导航配置、排序、筛选和连播设置不能绕过本规格；只调整与精简规则冲突的行为，沿用兼容的播放和外观偏好。
- 关闭 Android 对外部内容链接的接管，以及应用运行时由外部链接直达内容页面的处理；不能只删导航或命名路由而保留其他直达路径。
- 保持登录流程正常工作。关闭内容链接入口不能破坏登录所需的交互与回调。
- 首页退出账号后清除当前会话显示的数据，回到未登录状态。复用现有账号管理，不新增多账号能力。

### 实现范围与数据契约

- 主要修改应用启动与导航、稍后再看展示和推进、播放页周边内容与连播边界、设置入口及 Android 外部链接配置。
- 优先复用现有请求与组件，在现有结构中落实精简策略；不为此重写通用列表、账号系统或播放器。
- 稍后再看查询保持现有鉴权、排序、筛选和分页协议；完成操作保持现有服务端移除协议。没有新增服务端接口、持久化数据模型或数据库迁移要求。
- 实现时可以根据现有耦合选择最小改动位置，但不能仅通过修改偏好默认值或隐藏某一组导航来宣称功能完成。

## Testing Decisions

用户已确认以下测试边界：以“首页显示 → 打开播放 → 返回 → 点击完成”为主要边界，自动化验证单视频显示、顺序及删除成功／失败，再通过 Android 真机验收合集续播、播放控制和外部链接关闭。

### 测试边界与现有基础

- 测试可观察的用户行为与队列操作结果，不断言私有方法、组件层级、内部字段或具体实现步骤。
- 优先在稍后再看首页／应用流程的最高可行层编写 Flutter widget 或流程测试，以一组统一的队列读取与移除替换点提供固定响应。
- 优先复用现有请求边界。若现有静态调用无法方便地替换，仅为此流程提供一个小的、可替换的稍后再看数据边界；不为每个组件建立单独的测试接口。
- 现有项目已有 Flutter 测试依赖，以及账号删除后迟到响应不能恢复账号的生命周期测试，可参考其固定账号、临时存储和可控异步响应方式。
- 当前未发现稍后再看首页或播放器的现成流程测试。新增测试应覆盖本次行为变化，不重写既有账号测试或为简单显隐逐项创建镜像测试。
- 自动化测试使用固定队列和模拟移除结果，不依赖真实 B 站网络，也不删除真实账号的数据。
- 原生播放器、实际服务端同步及 Android 链接处理，通过真机补充验收，不在普通 widget 测试中模拟全部媒体引擎。

### 核心自动化验收

| 场景 | 可观察的通过条件 |
| --- | --- |
| 初始化与刷新 | 固定队列中最早添加的项目成为唯一展示项；已标记看完的项目同样参与排序 |
| 单视频限制 | 多项队列下只显示队首，滚动或改变窗口尺寸不能显示后续队列项，也没有跳过或队列浏览入口 |
| 播放后返回 | 没有点击完成时，返回首页仍显示原队列项；播放结束或观看进度变化不会删除项目 |
| 完成成功 | 只对首页当前项目发起移除；成功后显示服务端新的队首 |
| 完成失败与重复点击 | 请求未成功时保留当前项目并提示重试；同一请求期间重复点击不产生额外移除 |
| 移除成功但刷新失败 | 显示可重试读取状态，重试后显示正确队首，不再次移除已成功删除的项目 |
| 分页边界 | 超过一页的队列连续完成后仍按顺序展示，跨页不漏项、不重复已移除项 |
| 空队列与读取错误 | 空队列显示完成／空状态，读取错误显示重试状态，两者清楚区分 |
| 会话变化 | 退出或切换账号后，旧队列请求的迟到响应不能覆盖当前会话数据 |
| 合集与原始项目身份 | 播放页选到合集中的其他集后，回到首页完成时仍移除最初打开的队列项 |

以上场景可合并为少量完整行为测试；不要求按表格逐行拆成独立测试文件或重新验证所有既有播放能力。

### Android 真机验收

1. 冷启动、未登录、登录成功和退出账号流程正确；登录后直接进入单视频首页。
2. 从 B 站官方客户端或网页添加视频，刷新后出现正确队首；完成后在官方客户端确认该项目已被移除。
3. 普通视频、现有支持的视频类型、合集与多 P 视频正常播放；无法播放的队首仍能完成移除。
4. 合集和分 P 列表可展开、手动切换，并在内部自动续播；末尾停止，没有跨队列、相关推荐或循环续播。
5. 横竖屏和全屏切换后，选集、播放控制及精简入口保持正确。
6. 播放页没有评论、相关推荐、完整稍后再看队列或其他浏览入口；首页仅提供当前项目及必要操作。
7. 播放、字幕、弹幕和外观设置可正常使用，设置中不能恢复已隐藏功能或不允许的连播方式。
8. 在已有安装及旧偏好下升级验证，仍进入单视频首页，旧导航、筛选和连播配置不突破规则。
9. 从浏览器或其他应用打开 B 站内容链接时，本应用不接管链接或直达内容；应用已启动和未启动两种状态都检查，登录仍可正常完成。
10. 网络中断、读取失败及完成请求失败时，界面提示清楚，能重试，并保持服务端确认后才推进队列。

## Out of Scope

- 删除全部无关源码、清理依赖、减小安装包、重写架构或拆出独立播放器。
- iOS、Windows、Linux 等其他平台的运行、适配与验收。
- 搜索、推荐、动态、收藏夹、用户主页、私信、评论等浏览或社交功能。
- 在本应用添加视频、粘贴链接添加、分享接收添加或任意外部链接直接播放。
- 跳过、随机选择、排序切换、观看状态筛选、完整队列浏览、多选和批量清空。
- 播放结束后自动删除队列项、跨稍后再看队列自动续播、相关推荐续播或在播放页完成项目。
- 新增后端、本地独立队列、离线队列编辑、智能推荐、统计、奖励或专注时长功能。
- 新增下载／离线缓存入口、扩展登录方式、多账号能力、视频类型或其他播放功能。
- 品牌重命名、图标替换、大规模视觉重设计，以及对既有播放能力进行全面回归测试。

## Further Notes

- 本规格综合了本次逐项设计确认，未追加新一轮产品访谈。用户明确偏向减少干扰，并优先快速实现；接受保留冗余代码。
- 当前客户端的稍后再看是完整网格列表，提供“全部／未看完”筛选，默认最近添加；本规格将可见行为改为固定“全部”、最早添加和唯一队首。
